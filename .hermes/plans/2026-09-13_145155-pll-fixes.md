# Fix Plan: PLL Acquisition + False Lock + Consistency

## Goal

Fix the five review findings that affect device behavior (zero pull-in range, false lock, split frontends, single-sample window replay, `AdaptiveGain.reset` bug) plus the small hygiene items, with failing tests first for each, in `firmware/`, `tests/`, and 4 doc refs — no retuning of body constants.

## Current context / assumptions

- Review report: `docs/pll_workflow_review_2026-09-13.md` (read it first; all repro commands + observed outputs are there).
- Failing behavior is proven, not suspected: raw `PLL` tracks only its 6 Hz center (4/5/7/8/9 Hz park at ~6.0 unlocked; 12 Hz reports `locked=True` at 5.99); full `SuppressStage` chain reports `locked=True` at 6.00 for 4 Hz and 8 Hz inputs; drift 6→7 Hz ends 6.60 unlocked; `AdaptiveGain(initial_gain=0.9).reset().gain == 0.5`.
- The fix already exists as untested prototype: `prototype/loop2.py` — G1 gear-shift (wide loop while unlocked), G2 coarse zero-crossing seeding (recenters NCO when unlocked >1 s), B1 beat-aware lock (fast/slow EMAs + coarse-vs-NCO veto). Its docstring confirms the false-lock mechanism. Port it; do not invent a new algorithm.
- Decisions on the review's open questions (locked for this plan): `b7_fit`'s frontend (dominant-axis + normalized drive) is canonical — migrate `SuppressStage` to it; `prototype/` stays experimental, `firmware/` is source of truth; single-channel `abs()`-rectified drive is intended (pin it in a test, don't change it); body constants (`AMP_GATE`, `PREDICTION_MS`, fusion `W`) are NOT retuned here.
- Constraints: `firmware/` is MicroPython (stdlib only, no numpy — already true); no pytest in this env, so every verification uses `python tests/<file>.py` or `python <probe>`; work on branch `fix/pll-acquire-and-lock`; commit after every green task.
- Baseline before starting (must be green): `python tests/test_pll.py && python tests/test_suppress.py && python tests/test_b7_fit.py && python tests/test_actuate.py && python tests/test_adaptive_gain.py && python tests/test_anticancel.py && python tests/test_predictor.py` — each prints `* tests passed!`.

### Task 5 — Extract shared frontend `firmware/common/frontend.py` (5 min)

DRY: b7's proven frontend (per-axis DC removal + dominant-axis + bandpass + amplitude-normalized drive) becomes the single implementation `SuppressStage` and b7 both use. Create the file with exactly this content (constants mirror `combo_b7_fit.py` TODO-marked values; do NOT retune):

```python
"""common/frontend.py — canonical tremor frontend (ported from combo_b7_fit).

Per-axis gravity/DC removal -> dominant-axis projection -> bandpass 3-12 Hz
-> amplitude-smoothed, normalized PLL drive. Normalization keeps loop gain
constant across shakes (see review Blocker 2); raw amplitude is returned
untouched for output scaling.
"""

MEAN_ALPHA = 0.02  # TODO: tune on body — DC (gravity) tracker per axis
ENERGY_ALPHA = 0.02  # TODO: tune on body — axis-energy tracker
AMP_ALPHA = 0.05  # TODO: tune on body — amplitude smoother
NORM_EPS = 0.05  # PLL normalization floor (g)


class AxisFrontend:
    """Single-IMU frontend: xyz -> (pll_in, filt, amp)."""

    def __init__(self, bandpass):
        self._bp = bandpass
        self._mx, self._my, self._mz = 0.0, 0.0, 1.0
        self._ex, self._ey, self._ez = 0.0, 0.0, 0.0
        self._dom = 0
        self._amp_smooth = 0.0

    def step(self, x, y, z):
        self._mx += MEAN_ALPHA * (x - self._mx)
        self._my += MEAN_ALPHA * (y - self._my)
        self._mz += MEAN_ALPHA * (z - self._mz)
        ax, ay, az = x - self._mx, y - self._my, z - self._mz
        self._ex += ENERGY_ALPHA * (ax * ax - self._ex)
        self._ey += ENERGY_ALPHA * (ay * ay - self._ey)
        self._ez += ENERGY_ALPHA * (az * az - self._ez)
        if self._ey > self._ex and self._ey >= self._ez:
            self._dom = 1
        elif self._ez > self._ex and self._ez > self._ey:
            self._dom = 2
        else:
            self._dom = 0
        s = ax if self._dom == 0 else (ay if self._dom == 1 else az)
        filt = self._bp.process_sample(s)
        amp = abs(filt)
        self._amp_smooth += AMP_ALPHA * (amp - self._amp_smooth)
        pll_in = filt / (self._amp_smooth + NORM_EPS)
        return pll_in, filt, amp

    def reset(self):
        self._bp.reset()
        self._mx, self._my, self._mz = 0.0, 0.0, 1.0
        self._ex = self._ey = self._ez = 0.0
        self._dom = 0
        self._amp_smooth = 0.0
```

## Risks, tradeoffs, and open questions

- **Risk: port overshoot.** loop2's gains were tuned against its own prototype harness; the normalized-input hysteresis (H=0.3) and 30-sample veto are scaled for firmware ranges but unproven on-body. Mitigation: Tasks 2–4 keep thresholds identical to loop2 and verify against both synthetic probes AND the real-CSV replay in `test_actuate.py`; any regression there vetoes the port constants.
- **Risk: recentering fights the DNN gate.** `ActuationStage` resets PLL per window while G2 recenters on 1 s starvation — combined, lock may flap at window boundaries. Mitigation: Task 11's `test_actuate` replay must stay green; if flapping appears, scope G2 to b7/un-gated paths only (one-line guard: skip recenter when called from a resetting stage).
- **Risk: frontend swap changes actuate duties.** `SuppressStage` output feeds `ActuationStage`'s median-of-32; normalized drive rescales duties. The `test_postural_scales_below_kinetic` and CSV replay tests pin the envelope — trust them, and flag duty-magnitude shifts in the commit message rather than "fixing" test expectations.
- **Tradeoff: shared `frontend.py` vs inline duplication.** Extraction risks subtle drift (b7 behavior must be bit-identical after Task 7 — its amplitude-jump test is the tripwire); duplication risks the exact divergence that caused Finding 3. Extraction wins, with Task 7's escape hatch (sync comment) if bit-identity fails.
